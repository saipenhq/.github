# Contributing to SAIPEN HQ projects

Thanks for taking the time to improve something.

## Before opening a change

Use the repository that actually owns the code or documentation. SAIPEN HQ is the
ecosystem home, but many projects are currently hosted under
[`vacterro`](https://github.com/vacterro).

Project-local `CONTRIBUTING.md`, `SECURITY.md`, test commands, release rules,
and protocol files override this organization-wide default.

## Good issue reports

Please include:

- what you expected;
- what happened instead;
- exact version, commit, or release when known;
- operating system and relevant runtime/tool versions;
- minimal reproduction steps;
- logs or screenshots with credentials and private data removed.

For SAIPEN-governed repositories, include the relevant conformance/status output
when it materially helps reproduce the problem.

## Pull requests

Keep a pull request focused on one coherent change. Explain the user-visible or
engineering problem first, then the chosen fix and how it was verified.

Do not mix unrelated cleanup, generated churn, formatting sweeps, or speculative
rewrites into a functional fix unless the owning repository explicitly asks for
that work.

## AI-assisted changes

AI-assisted contributions are welcome. The contributor remains responsible for
the result.

Please verify generated changes, run the owning repository's required checks, and
do not present model output as evidence by itself. Existing generated or
agent-maintained documentation markers are intentional unless the owning
repository says otherwise.

## Community discussion

Use [SAIPEN Community on Discord](https://discord.gg/SEYaYkuVgN) for quick
questions, screenshots, brainstorming, and cross-project discussion.

Use GitHub Issues for reproducible bugs and durable feature requests.
