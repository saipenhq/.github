# Security Policy

## Reporting a vulnerability

Do not publish credentials, private data, exploit details, or a working
proof-of-concept for an unpatched vulnerability in a public issue.

First check whether the affected repository has its own `SECURITY.md`. A
repository-local security policy takes precedence over this organization default.

If no project-specific policy exists, contact the maintainer privately through a
non-public GitHub contact channel available on the maintainer profile. Include:

- affected repository and version/commit;
- impact;
- minimal reproduction;
- whether the issue is remotely reachable;
- any prerequisites or permissions required;
- suggested mitigation if known.

## Scope

Security reports should concern behavior controlled by the affected project.
Upstream vendor, operating-system, model-provider, or third-party service issues
should be reported to the corresponding owner unless the SAIPEN HQ project adds
a distinct vulnerability of its own.

Please avoid accessing data that is not yours, disrupting services, or expanding
testing beyond what is necessary to demonstrate the issue.
